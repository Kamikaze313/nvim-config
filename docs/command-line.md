# Floating command line with suggestions

Press **:** in normal mode to open a rounded command input near the top center.
The selected **folke/noice.nvim** plugin draws it with its required **nui.nvim**
helper. The existing **blink.cmp** supplies a dropdown of matching commands and
arguments as you type, using its bundled command-line provider.

## Brief usage

Restart Neovim and open `nvim init.lua`. Type **:colorscheme def** in normal mode.
Matching suggestions appear below the input, with no automatic selection.
Press **Down** to select
**default**, then **Enter** to accept and run `:colorscheme default` in one step.
This example changes the theme only
for the session; use the existing `:Theme` command to save a personal selection.

**Enter** runs exactly what you typed unless you deliberately select a suggestion
with **Down / Up** (or another browsing key). For example, **:q Enter** executes
only `:q`, even while suggestions are visible. After selecting a suggestion,
**Enter** accepts and executes it in one step. Browsing leaves the input untouched.
**Esc** cancels the input and closes both windows. **Ctrl-e** closes just the
suggestion menu so you can continue editing the command.

| Mode | Keys / command | Action |
| --- | --- | --- |
| Normal | `:` | Open the top command input (native). |
| Command line | `Down` / `Up`, `Tab` / `Shift-Tab`, `Ctrl-n` / `Ctrl-p` | Browse dropdown candidates without inserting text. Existing native behavior is the fallback without a menu. |
| Command line | `Ctrl-y` | Fill the selected candidate, or the first candidate when none is selected. |
| Command line | `Ctrl-Space` | Request suggestions manually. |
| Command line | `Ctrl-e` | Hide the dropdown while leaving the command input open. |
| Command line | `Enter` | With no selection, execute exactly the typed command. After explicitly selecting a suggestion, accept and execute it in one step. |
| Command line | `Esc` | Cancel the command and close the input/dropdown (native). |
| Normal | `Space c c` | Toggle both editor and command suggestions for this session; the input remains available. |
| Command | `:CompletionToggle` | Existing command for the same completion toggle. |
| Command | `:checkhealth noice` / `:checkhealth blink.cmp` | Open health reports; `:q` closes a report. |
| Command | `:help noice.nvim` / `:help blink-cmp` | Open upstream help; `:q` closes help. |
| Command | `:Noice disable` / `:Noice enable` | Temporarily return input to the bottom or restore the floating UI. |

The command-line mappings are generated by Blink and include its `blink.cmp: ...`
descriptions. No new leader shortcut is added. **/** and **?** searches, `input()`
prompts, and expression-register input use Noice's plain bottom command view;
they receive no Blink suggestions. Help and Lua command formats use Noice's
default icons. Command arguments include native command-specific candidates,
such as colorscheme names for `:colorscheme` and file paths for `:edit`.

## Dependencies and automatic behavior

- Neovim **0.9+** with LuaJIT and `vim.ui_attach`, lazy.nvim, and Git for installing
  plugins. This machine has Neovim **0.12.0-dev**.
- **MunifTanjim/nui.nvim** is a required plugin dependency; it draws Noice's input,
  border, and layout. It adds no selected editing feature of its own.
- **saghen/blink.cmp 1.x** is already selected and installed. Its bundled command
  provider and Lua matcher need no new source plugin, native binary, or compiler.
- The existing Nerd Font renders prompt and suggestion icons. No new font or
  icon provider is needed; see the [font guide](appearance.md#choose-fonts-in-kitty).
- Extra Tree-sitter parsers are optional for command syntax highlighting. Missing
  parsers use plain text; this feature does not install any additional parsers.

On a new device, run **:Lazy install**, wait for completion, and restart. To
install only this addition, use **:Lazy install noice.nvim nui.nvim**. Checkouts
live in `~/.local/share/nvim/lazy-selected/noice.nvim` and `nui.nvim`; lazy.nvim
generates their commits in `lazy-lock.json`. Updates and downloads remain manual.

Noice attaches on `VeryLazy` after startup and opens the input only while a
command is active. It publishes the input position for Blink to place its menu
under the bottom border. The input scales to 60% of the editor width. Blink
opens its menu automatically when candidates are available; the existing
completion toggle suppresses both editor and command candidates until re-enabled.
Noice's separate popupmenu, message/notification UI, LSP progress, hover,
signature help, and server-message handling are disabled. Native command output,
errors, and `:messages` remain available. The existing quit-text cleanup below
also remains active.

Noice's health report lists optional parsers and disabled LSP/notification
interfaces; these are not required dependencies for the selected command input.

## Configuration and disabling the floating UI

`lua/plugins/command-line.lua` contains the Noice specification, Nui dependency,
top position, width, rounded border, bottom search/input formats, and explicit
feature exclusions. `lua/plugins/completion.lua` contains Blink's `cmdline`
sources, controls, automatic menu, no-insertion policy, and menu-position callback.
Every setting is documented inline. `lua/config/lazy.lua` imports both explicitly.

For example, change `views.cmdline_popup.position.row = 3` to `1` to put the
input closer to the top; restart to apply. Change the width from `"60%"` to
`"75%"` for a wider input. Comment each changed setting and update README.md
and docs/features.md when changing the feature selection.

For a session-only change, run **:Noice disable**; **:Noice enable** restores the
floating input. Blink can continue completing commands at the native bottom
position. For permanent removal, remove `{ import = "plugins.command-line" }`
from `lua/config/lazy.lua` and restart. Noice and Nui can remain unused on disk.
To remove command completion as well, replace Blink's `cmdline` table with
`cmdline = { enabled = false }`, remove its menu-position override, and restart.
Keep the editor completion settings. Preserve `.backups/`, Git history/index,
and all previous plugin installations; update README.md and docs/features.md.

## Clear quit-command text after closing a window

After `:q` successfully closes a split or a tab's last window, the bottom
command line clears automatically. This fixes the executed `:q` staying visible.

### Cleanup usage

Open Neovim, run `:vsplit`, then type `:q` and press Enter without selecting a
suggestion. The second window closes and
the command line becomes blank. For a tab example, run `:tabnew`, then `:q`.

The action also handles `:qu`, `:qui`, `:quit`, and their `!` forms. Native quit
behavior still applies: `:q!` discards unsaved edits when Neovim allows it.
If a quit fails because of unsaved changes, its error stays visible; use `:w`
to save before retrying. Quitting the final window exits Neovim normally.

This cleanup itself adds no shortcut, plugin, dependency, or installation.
The selected floating command UI above closes independently when command entry ends.

### Cleanup configuration and automatic behavior

The `ClearQuitCommand` autocommand group in `lua/config/autocmds.lua` listens
for `CmdlineLeave` on `:`. It recognizes a submitted simple quit command,
then schedules a check after execution. It clears the displayed text with
`echo ""` only when the original window has closed, no new command line is
active, and no new error was reported. Canceled and failed quits are skipped.
The named group uses `clear = true` to prevent duplicate callbacks on reload.

Validation: startup and attached-UI checks passed for split/tab closure, quit
abbreviations, forced quits, visible unsaved-file errors, ordinary command output,
and closing/reopening the terminal while preserving its running shell.

### Disable the cleanup

Remove the `ClearQuitCommand` block from `lua/config/autocmds.lua` and restart
Neovim. For the current session only, run `:autocmd! ClearQuitCommand`.
Update README.md and docs/features.md when removing the configuration.
